النشر المجدول — ملفّ قرار

الجدولة مبنيّةٌ إلّا قطعةً واحدة. هذا الملفّ يقول ما هو قائمٌ بدليله، وما ينقص، وقراراً واحداً لا يُنفَّذ شيءٌ قبله.

الحكم

الموعد يُحفظ اليوم — ولا أحد يقرؤه لينشر. الناقص مسارُ كرونٍ واحد.

فُحص كلُّ مستهلكي scheduledAt في الأدمن والكونسول: إنشاءٌ · تعديلٌ · عرضٌ في الجدول · تصديرٌ إلى CSV. ولا موضعَ واحد يقارنه بالوقت الحاليّ.

والكودُ نفسُه يعترف — articles/workflow/actions/set-scheduled-date.ts:16:
«Sets scheduledAt — does NOT publish the article. Admin still has to either (a) come back and click Publish Now, or (b) wait for a future cron job that auto-publishes articles whose scheduledAt has passed.»

ما تعنيه «مجدول» — قُرئ من الكود لا من الاسم

«مجدول» = العميل وافق والمقال جاهزٌ للنشر — لا «له موعدٌ محدَّد».

الدليلما يقوله
console/lib/mobile-api/article-decisions.ts:26 الموافقة تكتب status: SCHEDULED فقط — ولا تكتب scheduledAt
admin/…/article-status-machine.ts:4 «The only way an article reaches SCHEDULED… is the client approving it»
admin/…/workflow/lib/transitions.ts:83 «Publish them now manually if you want to skip the scheduled date»

⇒ scheduledAt أداةُ تأخيرٍ اختياريّة، لا شرطٌ للنشر. والافتراضُ أنّ المقال يُنشر. ولهذا لا يُنشئه أحدٌ عند الموافقة: أغلبُ المقالات لا تحتاج تأجيلاً.

وهذا يُسقط ما كتبتُه سابقاً من أنّ «الكرون لن ينشر إلّا ما حُدِّد له موعدٌ بيد موظّف» — كان قراءةً خاطئةً للاسم لا للكود. والصحيحُ أدناه.

خطّة التنفيذ — خمس خطوات

١
استخراج النشر إلى دالّة مشتركة.

منطق النشر اليوم داخل transitionArticleAction (سيرفر أكشن لا يُنادى من مسار). يُنقل إلى lib/articles/publish-article.ts، فيناديه الزرُّ والكرون معاً.

هذا أهمّ بندٍ في الخطّة. لو نسخ الكرونُ المنطقَ لنفسه، صار للنشر بابان: واحدٌ يفحص السيو والالتزام، وآخر ينشر بلا فحصٍ عند منتصف الليل.
٢
مسار app/api/cron/publish-scheduled/route.ts.

نفسُ حارس السرّ أعلاه. يقرأ ويُرتّب الأقدم أوّلاً بسقفٍ يمنع تجاوز المهلة:

where: {
  status: "SCHEDULED",
  OR: [
    { scheduledAt: { lte: new Date() } },   // له موعدٌ وقد حلّ
    { scheduledAt: null },                  // بلا موعد — يُنشر فوراً
    { scheduledAt: { isSet: false } },      // الحقل غائبٌ أصلاً
  ],
}
orderBy: { scheduledAt: "asc" }
take: 20
الفرعان الأخيران ليسا تكراراً: على مونغو { field: null } لا يطابق وثيقةً لا تحمل الحقل (توثيق Prisma: «a non-existing field isn't equal to null»). وأغلبُ المقالات لا تحمله — فبفرعٍ واحد يتخطّاها الكرونُ كلَّها ولا ينشر شيئاً.
٣
لكلّ مقال: نداءُ الدالّة، والفشلُ لا يوقف البقيّة.

مقالٌ يسقط في بوّابة السيو أو فحص الالتزام لا يُنشر ناقصاً. ومصيرُه القرار الثاني أدناه.

٤
سطرٌ في vercel.json. 
{ "path": "/api/cron/publish-scheduled", "schedule": "*/15 * * * *" }

ربعُ ساعة لا دقيقة: القارئ لا يفرّق بين ١٠:٠٠ و١٠:١٤، وكلّ دورةٍ استعلامٌ على أطلس.

٥
تحقّقٌ حيّ على modonty_dev قبل الإنتاج.

مقالٌ بموعدٍ في الماضي ← نداءٌ يدويّ للمسار بالسرّ ← يُقاس: الحالة PUBLISHED · datePublished مختوم · ظاهرٌ على مدونتي · IndexNow أُرسل.

ثلاثةُ عوائق تمنع الكرون اليوم

١
النشر محبوسٌ خلف جلسة. 
const session = await auth();
if (!session) return { success: false, error: "Unauthorized" };
// transition-article.ts:31-32

الكرون بلا جلسة ⇒ الاستخراج إلى دالّةٍ مشتركة ليس تحسيناً بل شرطُ عمل.

٢
سجلّ التدقيق يصمت بلا جلسة. 
const userId = session?.user?.id;
if (!userId) return;   // لا سطر ولا خطأ
// lib/audit/log-action.ts:134-141
فأخطرُ فعلٍ عندنا — نشرٌ للعالم — سيجري آليّاً بلا أثرٍ واحد في السجلّ. وهذا أسوأُ من غياب الكرون نفسِه.
٣
الجدول لا يقبل فاعلاً نظاميّاً. 
userId    String  @db.ObjectId   // إلزاميّ
userEmail String                 // إلزاميّ
// schema.prisma:3844-3845

فلا يمكن كتابة «النظام» فاعلاً بلا جعل userId اختياريّاً — وهو تعديلُ سكيما يحتاج prisma db push على الإنتاج.

القرار الأوّل — أثرُ الكرون في سجلّ التدقيق

أ — تعديل السكيما: userId String? + userEmail "system:cron"

السجلُّ يبقى مصدراً واحداً لكلّ فعل، بشريّاً كان أو آليّاً. الكلفةُ prisma db push على الإنتاج — وهي خطوةٌ نفّذناها اليوم بلا عطل.

ب — بلا تعديل سكيما: الكرون يكتب في SystemError بمستوى «معلومة» + تنبيه تلغرامالمرشَّح

لا لمسَ للإنتاج، وأثرٌ يبقى قابلاً للقراءة في /system-errors. وعيبُه أنّ أثر النشر يسكن مكانين.

ج — بلا أثرٍ إطلاقاً

مرفوض. نشرٌ للعالم بلا سطرٍ يقول متى ولماذا.

القرار الثاني — المقال الذي يفشل في البوّابة

أ — يبقى مجدولاً ويُعاد كلّ ربع ساعة

لا يضيع الموعد، لكنّ نفس المقال يفشل ٩٦ مرّةً في اليوم — فيتحوّل التنبيه إلى ضجيجٍ يتجاهله الجميع، وهي نهايةُ كلّ طابورٍ يحاول بلا حدّ.

ب — يصير DRAFT بملاحظةٍ وتنبيهٍ واحدالمرشَّح

السببُ يُكتب في revisionNotes، وتنبيهُ تلغرام مرّةً واحدة (القناة قائمةٌ ومستعملةٌ في تسجيل المستخدمين). فيرى الموظّف عطلاً واحداً واضحاً بدل تسعٍ وتسعين تكراراً.

المطلوب منك: اختر أ أو ب.

ماذا يحدث فعليّاً بعد أوّل تشغيل

حالة المقالما يفعله الكرون
وافق العميل، بلا موعديُنشر في أوّل دورة (خلال ١٥ دقيقة)
له موعدٌ مضىيُنشر في أوّل دورة
له موعدٌ مستقبليّينتظره
سقط في بوّابة السيو أو الالتزاملا يُنشر — القرار أدناه
لم يوافق عليه العميل بعدلا يُمَسّ — ليس SCHEDULED أصلاً
أوّلُ دورةٍ تنشر كلَّ ما وافق عليه العملاء ولم يُنشر بعد — دفعةً واحدة. ولهذا يُقاس العددُ على الإنتاج قبل التشغيل (القسم التالي)، ويُبدأ بسقفٍ منخفض إن كان كبيراً.

ما لم يُقس بعد

عددُ المقالات في SCHEDULED على الإنتاج — وهو بالضبط عددُ ما سينشره الكرون في دورته الأولى. السايدبار المحلّيّ يعرض ٢، وهذا رقمُ قاعدة التجارب لا الإنتاج.
