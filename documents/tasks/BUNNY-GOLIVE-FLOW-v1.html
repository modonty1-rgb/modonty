T2bأولوية ٢تحويل القديم ← الجديد — بند مستقل يخصّ مدوّنتيصفر خسارة

زرّ idempotent في route الترحيل يقرأ كل الصور القائمة (نصوص الكيانات الستّة + اليتيمة + الهوية + القصّة) ويحوّلها صفوف Media مملوكة لمدوّنتي بعلاقات. يُجرَّب على التست أولاً، ثم يُعاد على بيانات الإنتاج الحقيقية بعد الـSync ضمن T5 — نفس الزرّ، بيانات حقيقية.

🔒 قاعدة صفر خسارة (قرار خالد): التحويل إضافي فقط — لا يحذف ولا يعدّل أي حقل نصّي قائم ولا أي ملف. القديم يبقى كما هو حتى يثبت الجديد بجولتي تحقّق مستقلّتين.

القائمة التفصيلية (نُقلت من خطة الـcore عند إقفالها 2026-07-31 — بالقياس المحدَّث):

☐ اليتيمة (clientId=null) → coreClientId — القياس: ٩ (كان ١٠؛ الفارق يُتحقّق عند التشغيل)
☐ روابط الكيانات المعبّأة (٤ وسوم + ١٤ تصنيف + ٧ صناعات — منها ١ بعلاقة لكلٍّ؛ المؤلفان حُذفا والطاقم أُلغي): إيجاد/إنشاء صفّ Media بالرابط نفسه مملوكاً لمدوّنتي + تعبئة العلاقة (زرّ، لا سكربت)
☐ روابط Settings الستّة (على ملفات platform/) → صفوف Media مملوكة
☐ صور القصّة ~١٧ (story/_constants.ts) → صفوف Media + fallback للثابت
☐ أصول brand-assets.ts الأربعة → صفوف Media، والقراءة: قاعدة أولاً ← الثابت fallback
☐ التحقق الختامي: صفر صورة منصّة بلا صفّ Media مملوك لمدوّنتي

قيد التصميم (قرار خالد): يُستخدم مرّة واحدة ثم يُحذف. لذلك يجب أن يكون مجلّداً واحداً مكتفياً بذاته — الصفحة والمكوّنات والأكشنز كلها بداخله، صفر ملف يخرج منه وصفر صفحة أخرى تستورد منه. حذف المجلّد + سطر واحد في القائمة الجانبية = الميزة اختفت بلا بقايا ولا كسر.
