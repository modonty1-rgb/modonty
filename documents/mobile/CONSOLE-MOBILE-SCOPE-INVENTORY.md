# جرد العميل — Console Mobile مقابل Console Web

**تاريخ الجرد:** 2026-08-28  
**الغرض:** تحديد ما يراه العميل وينجزه سريعاً من الجوال، وما يبقى في الويب. هذا
قرار نطاق، لا دليل على أن كل بند منفذ في تطبيق الجوال اليوم.

## قاعدة القرار

| الجوال | الويب |
|---|---|
| يرى معلومة مهمة، يتخذ قراراً واحداً، يرد بجملة، يفتح وجهة، أو يتابع حالة خلال دقيقة | ينشئ، يحرر محتوى طويلاً، يرتب عناصر كثيرة، يقارن بيانات، يرفع ملفات كثيرة، أو يدير إعدادات ومالاً وصلاحيات |

القاعدة لا تمنع قدرة من الجوال لأنها «متقدمة»؛ إذا كان لها فعل واحد واضح وبيانات قليلة
يمكن أن تصبح جوالاً. لكنها لا تُنقل كما هي من جدول أو محرر ويب.

## ما يجب أن يكون سريعاً على الجوال

| المجال | العميل يحتاجه على الجوال | الحالة في العقود الحالية | الوجهة |
|---|---|---|---|
| الرئيسية | ملخص الاشتراك، وعدد ما يحتاج قراراً، وHook العروض النشطة | `/api/mobile/v1/dashboard` موجود؛ Hook الإحالة عقد مقترح | جوال أساسي |
| اشتراكه | الحالة والأيام المتبقية، ثم تفاصيل الباقة عند الطلب | الملخص موجود داخل dashboard حالياً؛ endpoint تفاصيل مستقل مطلوب | جوال أساسي |
| مقالات بانتظار القرار | فتح المقال كاملاً بصيغة HTML، مراجعة أسئلة فريق المحتوى والمصادر لـYMYL، اعتماد أو طلب تعديل | قائمة/تفاصيل/اعتماد/طلب تعديل موجودة | جوال أساسي |
| المقالات المنشورة | قائمة مختصرة، ثم فتح المقال على موقع العميل العام | قائمة المقالات و`siteUrl` موجودان | جوال أساسي |
| أسئلة القراء | يرى الاسم والبريد والمقال، يرد أو يرفض السؤال | القراءة والرد والرفض موجودة | جوال أساسي |
| تعليقات القراء | يرى التعليق والمقال ويقبل/يرفض أو يرد بفعل واحد | القراءة موجودة في audience؛ أفعال التعليق للجوال غير موجودة بعد | جوال عند اكتمال العقد |
| فيديوهات/Reels | يرى الحالة وسبب الرفض/القبول ويفتح المعاينة | قائمة الفيديوهات موجودة؛ الرفع والقرار من الجوال ليسا عقداً فعلياً بعد | جوال متابعة أولاً |
| تنبيهات | قائمة الرسائل، غير المقروء، وفتح الوجهة الصحيحة | قائمة وعدد غير مقروء موجودان؛ تعليم القراءة وdeep links يحتاجان عقداً | جوال أساسي |
| عروض وإحالات | Hook نشط في الرئيسية ثم تفاصيله؛ التنبيه مجرد تذكير | لا يوجد Campaign/Referral/In-app inbox للعميل بعد | جوال بعد تنفيذ العقد |
| حجوزات | تنبيه بحجز جديد ثم فتح التفاصيل واتخاذ فعل واحد واضح | موجودة في الويب فقط حالياً | جوال بعد عقد مختصر |
| Leads | تنبيه بعميل محتمل مهم ثم فتح البيانات السريعة والاتصال/المتابعة | موجودة في الويب فقط حالياً | جوال بعد عقد مختصر |
| مراجعات العميل | تنبيه بمراجعة جديدة ثم قراءة ورد قصير | موجودة في الويب فقط حالياً | جوال بعد عقد مختصر |
| الدعم | قراءة آخر رد وفتح محادثة الدعم | شاشة جوال موجودة كواجهة؛ API الدعم للجوال غير موجود | جوال بعد عقد مختصر |
| الحساب | الملف الشخصي، تسجيل الخروج، الأجهزة، واختيار المظهر | تسجيل/حذف جهاز موجود؛ بقية العقد يحتاج مراجعة | جوال أساسي |

## ما يبقى للويب

| المجال | لماذا الويب هو السطح الصحيح |
|---|---|
| محرر الموقع والقالب والعنوان | نموذج متعدد الحقول مع معاينة وقرارات بنية الموقع |
| محتوى الصفحات وBlocks وFAQ الصفحة | ترتيب وإخفاء وإدارة عناصر عديدة ومحرر محتوى |
| ملف النشاط وYMYL والتراخيص وإقرار التنبيهات القانونية | مستندات وحقول حساسة ومراجعة دقيقة |
| SEO: intake، كلمات، منافسون، تقارير وتشخيص | جداول ومقارنات وحقول مطولة وتحليل متعدد المصدر |
| التحليلات الكاملة | مخططات، مدد زمنية، مقارنات وGA4 deep dive؛ الجوال يأخذ ملخصاً فقط لاحقاً |
| إدارة الصور والمعرض والفيديوهات والـReels | رفع متعدد، ترتيب، قص، وصف، وإدارة مكتبة |
| الحملات التسويقية وUTM | جداول، أهداف، ميزانية، وتجهيز حملات؛ الجوال يرى النتائج والتنبيهات فقط |
| قوائم المشتركين وLeads الكاملة | فرز، تصفية، تصدير، ومتابعات متعددة |
| الفواتير والدفع | بيانات مالية ومستندات وتنزيلات؛ الجوال يعرض حالة مختصرة فقط إن لزم |
| إعدادات الحساب الحساسة | كلمة المرور، Telegram، إعدادات التكامل، والصلاحيات |
| Site Health الكامل | تقارير PageSpeed وفئات تشخيصية؛ الجوال يكتفي بتنبيه حالة أو درجة موجزة |

## قدرات الويب الموجودة ولم تدخل الجوال بعد

- التحليلات، الحجوزات، الحملات، التعليقات، مراجعات العميل، المشتركين، Leads، الفواتير،
  الموقع، صفحات الموقع، المحتوى، الملف، SEO، Site Health، الدعم، والمعرض.
- لا يعني ذلك أن كلها يجب نقلها. لكل بند جوال في الجدول الأول endpoint صغير يملك فقط
  بيانات القرار والفعل المباشر؛ لا تنسخ الجدول أو API الويب.

## ما هو منفذ فعلاً في API الموبايل

| القدرة | الدليل |
|---|---|
| التوثيق والجلسة والأجهزة | `auth/login` · `auth/refresh` · `auth/logout` · `me` · `devices/register` · `devices/[deviceId]` |
| الرئيسية والاشتراك المختصر | `api/mobile/v1/dashboard/route.ts` |
| المقالات وقبولها/تعديلها | `articles` · `articles/[articleId]` · `approve` · `request-changes` |
| أسئلة فريق المحتوى داخل المقال | `articles/[articleId]/faqs/[faqId]/approve|reject` |
| أسئلة القراء | `audience` · `questions/[faqId]/reply|reject` |
| التنبيهات | `notifications` |
| الفيديوهات | `videos` |

## الترتيب المقترح بعد اعتماد واجهات المقالات والرئيسية

1. تثبيت مسارات الإنتاج الحالية: الرئيسية، الاشتراك، المقالات، مراجعة المقال، أسئلة
   القراء، والتنبيهات.
2. إكمال أفعال التعليقات ثم فيديوهات المراجعة؛ هذه قرارات يومية مناسبة للجوال.
3. تصميم العقود المختصرة للحجوزات وLeads والمراجعات والدعم، بحسب أولويات الاستخدام
   الفعلية، واحداً واحداً.
4. لا ننقل محررات الموقع وSEO والتحليلات والفواتير إلى الجوال؛ نضيف لها تنبيهاً أو
   ملخصاً فقط عندما يثبت أن العميل يحتاجه سريعاً.

## مصادر الجرد في المستودع

- تكوين تنقل الويب: `console/app/(dashboard)/components/nav-config.ts`.
- واجهات API الموبايل: `console/app/api/mobile/v1/`.
- شاشات الموبايل الحالية: `console-mobile/src/routes/`.
- العقد التفصيلي للمقالات والأسئلة: `articles/[articleId]/route.ts` و`audience/route.ts`.

## قيود التنفيذ

- كل شاشة جوال جديدة تمر بالصورة المعتمدة ثم tokens/components ثم لقطة Android فعلية.
- كل surface يطلب بياناته الأدنى فقط؛ لا يحمل الويب أو تفاصيل شاشة أخرى داخل dashboard.
- الحقل أو الفعل الغائب في API يُحذف من واجهة الجوال، لا يُختلق.
