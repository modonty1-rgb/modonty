# فصل عمل الموبايل — UI لاعتماد خالد / هندسة داخلية

**الحالة:** مرحلة اعتماد UI فقط. لا يتغير تطبيق الجوال قبل اعتماد الصورة الخاصة بكل
شاشة وفق `UIUX-RULES.md`.

## ١. ما يظهر لخالد الآن — طابور UI

هذه هي الشاشات التي تحتاج مراجعة بصرية وقراراً من خالد. يراجعها من لوحة
`SCREEN-SCAN.png` بالمعرف فقط؛ لا يحتاج أن يراجع APIs أو مكونات داخلية في هذه المرحلة.

| الترتيب | المعرّف | السطح | القرار المطلوب |
|---:|---|---|---|
| 1 | S02 | الرئيسية | اعتماد ترتيب Hook الإحالة ثم الاشتراك ثم المهام، وشكل كل bar مشترك |
| 2 | S03 | تفاصيل الإحالة | أول انتقال في الرئيسية: شرح الشهر المجاني، ثم CTA بعد اعتماد طريقة الإحالة |
| 3 | S04 | تفاصيل الاشتراك | ثاني انتقال في الرئيسية: الباقة والاستهلاك والتواريخ والسعر |
| 4 | S05 | مقالات بانتظار القرار | أول صف مهمة: قائمة قرار منفصلة عن المنشور وشكل حالة القرار |
| 5 | S06 | مراجعة المقال | HTML، الصورة، أسئلة فريق المحتوى، citations لـYMYL، والاعتماد/طلب التعديل |
| 6 | S07 | أسئلة القرّاء والتعليقات | صفوف المهام التالية: ترتيب النوعين وفهم المصدر والحالة قبل الفتح |
| 7 | S08 | الرد على سؤال قارئ | القراءة، كتابة الرد، الرفض، والتأكيدات |
| 8 | S09 | الفيديوهات | صف المهمة التالي: متابعة الحالة والمعاينة وسبب الرفض إن وجد |
| 9 | S10 | رفع الفيديو | تابع الفيديوهات عند اعتماده في نطاق المنتج |
| 10 | S11 | المقالات المنشورة | من تبويب المقالات: بطاقة المقال وفتحه على موقع العميل العام |
| 11 | S12 | التنبيهات | من تبويب التنبيهات: بطاقة رسالة واحدة، غير المقروء، والوجهة عند الضغط |
| 12 | S13 | الحساب | الملف، الأجهزة، تسجيل الخروج، واختيار المظهر |
| 13 | S14 | الدعم | قائمة الرسائل ومحادثة دعم قصيرة |

### شاشات لا نرسمها الآن

- محرر الموقع، SEO، التحليلات المفصلة، معرض الوسائط، الحملات، الفواتير، وإعدادات
  التكامل: ويب فقط، فلا تدخل طابور UI الموبايل.
- الحجوزات وLeads ومراجعات العميل: تحتاج قرار أولوية تجاري قبل أن تدخل طابور UI.
  إن تقرر إدخال واحد منها، نصمم له سطحاً سريعاً واحداً لا نسخة من جدول الويب.

## ٢. ما أحتفظ به داخلياً — Backlog هندسي

هذه البنود لا تحتاج قرار UI منك الآن. لا أنفذها قبل أن تكتمل صور الشاشات ذات الصلة،
لكنها مسجلة حتى لا تضيع عند الانتقال للتنفيذ.

| الأولوية | العمل الداخلي | الدليل/سبب الحاجة | يتبع اعتماد UI |
|---:|---|---|---|
| P0 | بناء AppShell وnative tabs وnative stack ومكونات bars المشتركة من tokens | الشاشات الحالية ليست عقد إنتاج بعد | S02 وما يستخدم مكوناتها |
| P0 | استبدال الواجهات fixture بعقود API الفعلية | `console-mobile/src/data/client-fixtures.ts` ما زال موجوداً | كل شاشة تعتمد |
| P0 | فصل `/subscription` عن `/dashboard` | dashboard يعيد تفاصيل لا تحتاجها الرئيسية | S02 وS04 |
| P0 | مكون ArticleCard موحّد وFlashList لعروض المقالات | القاعدة الهندسية تلزم FlashList و`memo` | S05 وS11 |
| P0 | HTML آمن للمقال + عرض featuredImage بـexpo-image | المقال محفوظ HTML وصورة المقال لها معيار 16:9 | S06 |
| P0 | تكملة حالة الأسئلة والتعليقات: loading/empty/error/offline وتأكيدات الفعل | endpoints القائمة موجودة لكن لكل سطح أربع حالات إلزامية | S07 وS08 |
| P0 | التعليمات ولقطة Android فعلية وoverlay/diff بعد التنفيذ | بوابة التسليم الحاكمة | كل شاشة بعد اعتمادها |
| P1 | تعليم قراءة التنبيه وdeep link لوجهته | `notifications` يعيد القائمة فقط حالياً | S12 |
| P1 | عقد Campaign وIn-app message وReferral و`activeCampaignHook` | لا يوجد في السكيمة الآن Campaign/Referral/Inbox للعميل | S02 وS03 |
| P1 | آلية إثبات الإحالة والاستحقاق idempotent وسجل تدقيق | لا يمكن منح شهر مجاني بموثوقية من دونها | S03 CTA |
| P1 | أفعال تعليقات القراء من الموبايل | audience يعيد التعليقات، لا توجد أفعال جوال لها | S07 |
| P1 | عقد فيديو للمراجعة/الرفع إن اعتمد في UI | API الفيديو الحالي قائمة فقط | S09 وS10 |
| P1 | عقد API للدعم والحساب والأجهزة | بعض الشاشات مرسومة قبل توفر العقود | S13 وS14 |
| P2 | عقود مختصرة للحجوزات وLeads ومراجعات العميل | موجودة في الويب فقط؛ لا تنقل الجداول للجوال | فقط بعد قرار الأولوية |

## ٣. طريقة العمل من الآن

1. خالد يقول المعرف: مثال `S03` أو `S10`.
2. أعدل صورة ذلك المعرف فقط في الخلفية وأحدث `SCREEN-SCAN.png`.
3. خالد يعتمد الصورة أو يعطي ملاحظة بالمعرف.
4. بعد اعتماد المجموعة المطلوبة، أنفذ Backlog الخاص بها من tokens والمكونات وعقود API.
5. لا أقول إن التنفيذ مكتمل إلا بلقطة Android فعلية ومقارنة بالصورة المعتمدة.

## ٤. نقطة البداية الحالية

- `S02`: **APPROVED بصرياً فقط** — Hook الإحالة الكهرماني الهادئ، الاشتراك، والمهام الأربعة؛ تعرض
  الصورة أعداد الصفر أيضاً لاختبار الشكل الكامل قبل الإنتاج. تسميات المهام تصف الحالة، لا تعطي أمراً؛
  مثالها: «مقالات بانتظار قرارك» والعدد مستقل.
- `S01`: **APPROVED بصرياً فقط**.
- `S03` هو أول سطح منطقي بعد اعتماد S02: تفاصيل الإحالة، ثم نتابع الترقيم من الأعلى إلى الأسفل.
