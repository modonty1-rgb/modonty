الناقص — كلّه في مدونتي (نطاقي)

#الناقصالدليل
١الخلاصة تفلتر الصور فقط — الفيديو المعتمَد غير مرئيّ رغم أنه PUBLISHEDget-reels-feed-page.ts · mimeType:"image/"
٢لا مشغّل <video> — يرسم صوراً فقطreels-feed-client.tsx
٣لا يُصدَر VideoObject في مدونتي — رغم أن الأرضية مُجهَّزة بالأعلىبحث @type VideoObject في مدونتي = صفر
٤لا صفحة مشاهدة مستقلّة /reels/[slug] — reelSlug يشير للعدملا reels/[slug]/page.tsx في مدونتي

✅ الأساس الموجود وجيّد

  • طبقة ملء الشاشة fixed inset-0 فوق الهيدر والفوتر.
  • تمرير خطّاف snap-y snap-mandatory — طلّة واحدة تملأ الشاشة.
  • تمرير لا نهائي عبر IntersectionObserver + مؤشّر (rootMargin: 200%).
  • حالة الإعجاب/الحفظ لكل مستخدم خارج الكاش المشترك — صحيح.
  • content-visibility:auto — المتصفّح يتخطّى رسم الطلّات البعيدة.

✅ بنية الفيديو جاهزة في السكيما

  • schema.prisma:1584 — bunnyVideoId (معرّف بني ستريم).
  • schema.prisma:1585 — playbackUrl (قائمة HLS).
  • بني ستريم مزوَّد بالكامل: مكتبة 698133، المفاتيح فعّالة، وMP4 fallback مُفعّل.
  • الرفع موجود: shared/lib/bunny-stream.ts (رفع TUS).
  • النطاقان مسجَّلان في next.config.ts — لا تعديل إعداد.
الفجوة في جملة: عندنا خلاصة صور بعظام سليمة، وبنية بني ستريم كاملة — والناقص هو مشغّل الفيديو نفسه (hls.js غير مركَّب) وربط حقول الفيديو بالخلاصة. هذا ما تبنيه الخطّة.

٢ كيف تشغّلها المنصّات الكبيرة

تيك توك · إنستغرام ريلز · سناب — النمط واحد، وموثّق هندسياً.

المصادر الأربعة (مهندسو Mux، وتحليل بنية إنستغرام، ومكتبات بركة المشغّلات) تتقاطع على خمسة مبادئ. صفحتنا اليوم تطبّق اثنين منها؛ الخطّة تضيف الثلاثة الباقية:

المبدأماذا يعنيعندنا اليوم
بثّ متكيّف HLSالفيديو مقطّع لأجزاء ٢-٣ ثوانٍ، والجودة تتبع الشبكة تلقائياًناقص
بركة مشغّلات٣-٥ عناصر <video> يُعاد تدويرها، لا واحد لكل طلّةناقص

لماذا هذا يعطي «السلاسة»؟ السلاسة ليست سرعة الشبكة — هي إخفاء زمن التحميل: المصغّرة تملأ العين في الإطار الأول، والفيديو التالي يكون مخزَّناً قبل أن تصله، فالانتقال يبدو فورياً لأن العمل تمّ قبل لحظته. هذا بالضبط ما يفعله بني: يعطينا HLS + مصغّرة + MP4 احتياطي من نفس المصدر.

سلّم الاحتياط — لا طلّة تبقى سوداء

١) Safari / iOS → <video> يشغّل HLS أصلاً بلا مكتبة (video.canPlayType('application/vnd.apple.mpegurl')) ٢) Chrome/Edge/Firefox → hls.js يربط الـHLS بالـ<video> (Hls.isSupported()) ٣) فشل hls.js أو متصفّح قديم → MP4 مباشر من بني play_720p.mp4 (الاحتياطي مُفعّل أصلاً) وفوق الثلاثة جميعاً: poster = thumbnail.jpg يظهر فوراً في كل الحالات

حلقة التنشيط (مراقب التقاطع)

IntersectionObserver threshold: 0.6 ├─ طلّة ≥ ٦٠٪ ظاهرة → تصير "النشطة": play() (صامتة تلقائياً) ├─ الطلّات الأخرى → pause() + currentTime=0 └─ عند تغيّر النشطة → حرّك نافذة الحياة (prev/current/next) وابدأ تسخين next عبر hls.startLoad()

٤ روابط بني ستريم — من التوثيق الرسمي

bunny.net/docs النطاق vz-a26f5478-719.b-cdn.net · مكتبة 698133 — كلاهما مسجَّل في next.config.ts

// من bunnyVideoId المخزَّن في Media، نبني كل شيء بلا نداء API إضافي:
const host = "https://vz-a26f5478-719.b-cdn.net";

HLS      → `${host}/${bunnyVideoId}/playlist.m3u8`
MP4      → `${host}/${bunnyVideoId}/play_720p.mp4`   // احتياطي
مصغّرة   → `${host}/${bunnyVideoId}/thumbnail.jpg`   // poster فوري
معاينة   → `${host}/${bunnyVideoId}/preview.webp`   // اختياري: hover
لماذا نبني الرابط بدل تخزينه؟ playbackUrl موجود في السكيما، لكن اشتقاق الرابط من bunnyVideoId يعني أن الأربعة (HLS · MP4 · مصغّرة · معاينة) تأتي من حقل واحد، فلا يتفرّقان ولا يتقادم أحدهما. نفس مبدأ «مصدر واحد» الذي يحكم بقيّة الموقع.

٥ إعداد hls.js — من التوثيق الرسمي

video-dev/hls.js · docs/API.md قيم مضبوطة لخلاصة قصيرة على شبكة جوّال

new Hls({
  // بدء يدوي: نتحكّم متى يبدأ التخزين (للتسخين المُسبق)
  autoStartLoad: false,
  // لا نجلب 1080p لعمود 420 بكسل — يتبع حجم المشغّل
  capLevelToPlayerSize: true,
  // خلاصة قصيرة: تخزين محدود يوفّر الذاكرة والباقة
  maxBufferLength: 10,
  maxMaxBufferLength: 20,
  backBufferLength: 6,
  // فيديو مسجَّل لا بثّ حيّ → نطفئ وضع الكمون المنخفض
  lowLatencyMode: false,
  // عامل يشغّل فكّ الترميز خارج الخيط الرئيسي → تمرير أنعم
  enableWorker: true,
  // احترام "توفير البيانات" على شبكات مصر الجوّالة
  startLevel: -1,
});

التسخين: نحمّل بلا تشغيل

// الطلّة التالية: نربط ونبدأ التخزين، بلا play()
hls.attachMedia(nextVideoEl);
hls.loadSource(nextHlsUrl);
hls.startLoad();            // يملأ المخزّن مقدّماً
// حين تصبح نشطة لاحقاً: nextVideoEl.play() → فوري، المخزّن جاهز
قرار تبعية hls.js مكتبة جديدة خارج الاستاك الحالي (~٤٠٠ ك.ب). لكنها المعيار الصناعي، وبني يُخرج HLS، وتُحمَّل عبر dynamic import على مسار الطلّات فقط — صفر بايت على بقيّة الموقع، وصفر على Safari (تشغيل أصلي). تحتاج موافقتك الصريحة قبل التركيب.
