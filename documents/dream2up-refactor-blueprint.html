DREAMTOAPP / REFACTOR BLUEPRINT

إعادة بناء الموقع على أساس واضح، خفيف، وقابل للنمو.

هذه ليست عملية تجميل لصفحات قديمة. سنفصل بين ما يخدم العميل ويعمل فعلاً، وما هو تكرار أو زخرفة أو JavaScript غير ضروري، ثم نبني الواجهة على نظام Ember Studio الدافئ والمنضبط.

الرؤيةالنظامالمراحلالحدودتعريف النجاح

1. الاتجاه العام

dreamToapp وكالة رقمية عملية وواثقة. العميل يجب أن يفهم خلال ثوان: من نحن، ماذا نبني، كيف يبدأ، وما الخطوة التالية. لا مؤثرات تعمل بدل الرسالة، ولا واجهة مزدحمة تريد إثبات أنها حديثة.

2. النظام البصري

اللون

خلفية #FAFAF9، نص #1C1917، Terracotta #C2410C للقرار والـCTA، وأصفر #F59E0B للتأكيد المحدود. لا تدرجات زخرفية.

الشكل

مساحة بيضاء متعمدة، خطوط فصل هادئة، عناصر التحكم 8px، والكروت 12px فقط حين تكون هناك مجموعة قابلة للمقارنة أو الإجراء.

الحركة

الحركة تخدم الحالة فقط: فتح قائمة، انتقال صفحة، إرسال نموذج. لا parallax، لا خلفيات متحركة، لا glow أو glass بلا وظيفة.

3. خطة التنفيذ

PHASE 00–01

الجرد والأساس

  • حصر المسارات والعقود والتبعيات.
  • تثبيت tokens المشتركة.
  • تحديث Button / Card / Input / Textarea.
  • لا حذف قبل إثبات عدم وجود callers.

تمت المراجعة والتصحيح.

PHASE 02

الهيكل العام

  • Navbar وMobile Menu وCTA وFooter.
  • حفظ اللغات، الروابط، الصلاحيات، وسلوك القائمة.
  • إزالة الزخارف من shell أولاً.

هذه المرحلة التالية.

PHASE 03

الصفحة الرئيسية

  • رسالة الوكالة وCTA واحد.
  • الخدمات، الأعمال، الطريقة، ونقطة البدء.
  • نبني قصة واضحة، لا مجموعة كروت تسويقية.
PHASE 04

المسارات العامة

  • الخدمات والمشاريع والصفحات التعريفية.
  • توحيد العناوين، المسافات، الحالات الفارغة.
  • مراجعة SEO والـmetadata لكل مسار.
PHASE 05

بدء المشروع والتواصل

  • تبسيط رحلة العميل للنموذج.
  • الحفاظ على validation وAPI والعقود.
  • رسائل نجاح وخطأ عملية وواضحة.
PHASE 06

لوحة العميل والتنظيف

  • واجهة تشغيلية كثيفة وواضحة، لا تسويقية.
  • إزالة dead code بعد التحقق.
  • قياس bundle وclient components والتحقق النهائي.

4. ما لا نلمسه بلا سبب واضح

عقود يجب حفظها

  • المسارات والروابط المحلية next-intl.
  • Prisma وMongoDB وCloudinary.
  • API actions والنماذج وvalidation.
  • الصلاحيات والمصادقة وبيانات Dashboard.

قواعد العمل مع Copilot

  • مرحلة واحدة ذات نطاق محدد.
  • تقرير في .agents/reports/copilot بعد التنفيذ.
  • لا dependencies أو migrations أو حذف جماعي.
  • مراجعة diff قبل الانتقال للمرحلة التالية.
