قواعد UI الملزمة

Console Mobile · إصدار 1.0 · مرجع التنفيذ قبل بناء أي شاشة

الصورة التي تعتمدها هي مواصفة التنفيذ. لا نبدأ شاشة جديدة قبل أن تجتاز الشاشة الحالية بوابة التسليم.

بوابة التسليم

  • صورة معتمدة أو امتداد مباشر لتصميم معتمد.
  • اختبار Android فعلي وعرض iPhone مرجعي.
  • Safe Area، RTL، والحالات الأساسية مكتملة.
  • كل هدف لمس 48×48dp أو أكثر.
  • الأيقونات من ModontyIcon فقط.
  • لقطة جهاز فعلي قورنت بالصورة قبل العرض.

1. Safe Area والهيكل

  1. الهيدر: 56dp للمحتوى + insets.top.
  2. الفوتر: 64–72dp + insets.bottom، والـscroll يحجز مساحته.
  3. الخلفية تصل للحافة؛ النص والأزرار لا تدخل status bar أو gesture area.
  4. لا قياس شاشة ثابت ولا absolute لتثبيت محتوى الصفحة.
  5. اختبار: 360×800، 390×844، 430×932، و720×1600 الفعلي.

2. التنقل والعودة للرئيسية

  1. التابات للأقسام العليا: الرئيسية، المقالات، الفيديوهات، الجمهور، التنبيهات.
  2. Home هو أول tab في ترتيب RTL، لا وظيفة مخفية في الشعار.
  3. Back يعيد خطوة؛ Home ينقل مباشرة للرئيسية. لا نخلطهما.
  4. Account في avatar، والثانوي في hamburger؛ لا tab سادس بلا قرار UI.
  5. التاب لا ينفذ upload أو approve؛ الأفعال داخل الشاشة.
  6. كل Drawer أو Modal له زر إغلاق مرئي 48dp، مع الضغط خارج العنصر وزر النظام Back.

3. اللمس والحركة

  • الحد الأدنى 48×48dp؛ الرمز 20–24dp داخل الهدف.
  • CTA أساسي واحد في الـviewport. المدمر لا يكون primary ولا بنقرة واحدة.
  • لا swipe كمسار وحيد؛ كل فعل له بديل وfeedback فوري.

4. الخطوط

Bold 700 ليس default. Regular للمحتوى، Medium للعناوين والأزرار، وBold فقط لقرار أو رقم حرج واحد.

  • لا Light أو Thin.
  • المحتوى يدعم تكبير النظام؛ tab وbadge لا يكبران بطريقة تكسر التخطيط.
  • عنوان البطاقة سطران؛ النص الطويل يلتف أو له “عرض الكل”.

5. الشكل، RTL، والأيقونات

  • المسافات: 4، 8، 12، 16، 20، 24، 32 فقط.
  • الحواف 16–20dp؛ Radius: input 12، button 16، card 20.
  • dark/light عبر semantic tokens؛ لا hex عشوائي داخل Route.
  • الحالة = نص + رمز/شكل + لون.
  • التطبيق RTL؛ email وURL والكود والأرقام التقنية LTR.
  • الأيقونات من src/components/brand/icons/ModontyIcon.tsx. غير الموجودة تُعتمد في الـmaster أولًا.

6. الحالات والوصولية

  • لكل شاشة: loading، populated، empty، error، offline/refresh، disabled.
  • loading = skeleton؛ error = سبب مختصر + retry؛ submit يمنع double submit.
  • Dummy data عربية واقعية ومتفاوتة الطول؛ لا Lorem Ipsum.
  • لكل Pressable role وlabel عربي. اختبار قارئ الشاشة وتكبير الخط وdark/light والـkeyboard.

الفلو الإلزامي

نطاق الشاشة + dummy data  →  صورة واحدة معتمدة  →  تنفيذ من tokens + components  →  لقطة جهاز فعلي ومقارنة  →  تعديل ذاتي ثم عرض النتيجة
