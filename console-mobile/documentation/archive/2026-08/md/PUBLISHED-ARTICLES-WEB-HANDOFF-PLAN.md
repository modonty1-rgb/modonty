# خطة تحويل المقالات المنشورة إلى موقع العميل

## الحالة

قرار المنتج معتمد: للمقال المنشور زر صريح يفتح صفحة مقالات موقع العميل العامة في Chrome. لا يوجد انتقال من بطاقة المقال نفسها.

## الحدّ الفاصل غير القابل للخلط

| حالة المقال | مكان التفاعل |
|---|---|
| منشور | يفتح موقع العميل العام في Chrome وفق قرار تجربة الاستخدام النهائي. |
| بانتظار تعميد | يبقى داخل تطبيق الكونسول: مراجعة المقال، الأسئلة، المصادر، الاعتماد أو طلب التعديل. |
| يحتاج تعديل | يبقى داخل تطبيق الكونسول حتى يستوفي القرار المطلوب. |

لا يفتح أي مقال غير منشور موقع العميل العام، ولا يُعامل كأنه نتيجة مكتملة للعميل.

## هدف المسار المنشور

إظهار نتيجة العمل للعميل على موقعه العام، ثم إتاحة اكتشاف المدونة وبقية المحتوى. هذا هدف تجربة واكتشاف، وليس ادعاءً بتحسين SEO من انتقال العميل وحده.

## الفلو المقترح — معلّق على اعتماد التصميم

```text
تاب المقالات المنشورة في الكونسول
→ فعل واضح يبين أن الوجهة هي المتصفح وموقع العميل
→ Chrome
→ صفحة مدونة العميل العامة
→ المقال المنشور ظاهر في أول مساحة مرئية
→ تصفح طبيعي لمقالات الموقع
→ رجوع النظام يعيد العميل عبر سجل Chrome ثم إلى الكونسول
```

البطاقة للعرض فقط؛ زر واحد صريح فيها هو فعل الانتقال. النص والرابط يخرجان من API، ويحذف الزر عندما لا يعيد المصدر `articlesBaseUrl` أو نص الفعل.

## الرابط والـSEO

- المصدر العام يبقى رابط موقع العميل القابل للزحف ونسخة الـcanonical للمقال.
- التطبيق لا يخلق رابطاً موازياً للمحتوى المنشور.
- قبل التنفيذ يراجع الرابط العام الفعلي ومكان ظهور المقال في قائمة المدونة، لا يُخمن مسار URL.

المصادر الرسمية:

- [Google Search: الروابط القابلة للزحف](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)
- [Android App Links](https://developer.android.com/training/app-links/about)

## خطة التتبع قبل التنفيذ

1. راجع أولاً نظام analytics الموجود في `console-mobile` و`console`؛ لا تُنشأ تسمية حدث جديدة قبل معرفة نمط الأحداث المعتمد.
2. وثّق الحدث المعتمد لبدء الانتقال من الكونسول إلى موقع العميل، مع ربطه بحالة المقال المنشور فقط.
3. وثّق وجهة الرابط الفعلية ونتيجة فتحه، من دون إرسال نص المقال أو بيانات العميل الحساسة إلى التتبع.
4. تحقّق من مسار الوصول إلى صفحة المدونة: هل المقال المقصود ظاهر فعلاً في أول مساحة مرئية؟
5. حدّد مع خالد تعريف نجاح قابل للقياس قبل جمع أي بيانات: فتح الموقع، بدء تصفح المدونة، أو رجوع العميل إلى الكونسول.
6. اختبر على جهاز أندرويد حقيقي: فتح Chrome، التصفح، الرجوع، والرابط غير المتاح أو بلا شبكة.

## قبل التنفيذ

- [x] صورة اعتماد لتاب المقالات المنشورة فقط.
- [x] قرار خالد على طبيعة ضغط البطاقة: زر صريح، لا ضغط البطاقة.
- [ ] مراجعة نظام analytics الحالي وتسمياته.
- [ ] مراجعة رابط موقع العميل الحقيقي وموقع المقال في صفحة المدونة.
- [ ] حالات تحميل وفارغ وخطأ وبلا شبكة داخل التطبيق.
- [ ] لقطة جهاز أندرويد فعلي قبل وبعد فتح الموقع.

## خارج النطاق حالياً

- تحويل مقالات بانتظار التعميد أو التي تحتاج تعديلاً إلى Chrome.
- WebView داخل تطبيق الكونسول.
- إنشاء deep link أو App Link قبل اعتماد خريطة الرابط العام والموقع.
- إنشاء أحداث تتبع أو حقول تحليل جديدة بلا مراجعة النظام الحالي واعتماد خالد.
