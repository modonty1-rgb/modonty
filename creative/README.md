# creative — أصول الصور والبرومبتات

مكان واحد لكل ما يخصّ توليد الصور والملصقات: الشعارات، الألوان، ونصوص البرومبت
جاهزة للنسخ. خالد يشتغل من هنا مباشرةً.

```
creative/
  brand/                          الأصول التي تُرفَع مع البرومبت
    modonty-icon.svg              شعار المنصّة
    modonty-verified-badge.svg    شارة «موثّق» — خلفية داكنة
    modonty-verified-badge-light.svg   شارة «موثّق» — خلفية فاتحة
    brand-colors.md               اللوحة وقاعدة استعمالها
  prompts/
    poster-dark-to-light.json     ← الصق هذا (الأدقّ)
    poster-dark-to-light.md       نفسه نثراً، لو احتجت تقرأه بعينك
    fixes.json                    تصحيحات جاهزة، واحدة لكل مشكلة
```

## الطريقة

1. ارفع صورتك + `brand/modonty-icon.svg` + `brand/modonty-verified-badge-light.svg`.
2. الصق محتوى **`poster-dark-to-light.json`** كما هو، بلا أي كلام قبله أو بعده.
3. لو الناتج ناقص، افتح `fixes.json` وألصق قيمة `send` للحالة المطابقة — **لا تعيد
   البرومبت كلّه**، الإعادة تخلط النموذج ويرجع لأخطاء صحّحتها.

## ليش JSON لا نثر

النثر يقبل التأويل: «صغير ومحترم» يفهمها النموذج كما يشاء. الJSON يفصل ما **يبقى**
(`preserve_exactly`) عمّا **يتغيّر** (`change_only`)، ويجعل الممنوعات قائمة صريحة
(`hard_constraints`) بدل جملة تضيع وسط الفقرة. أقلّ جولات ذهاب وإياب.

النسخة النثرية موجودة للقراءة فقط — الرسمية هي الJSON.

## قاعدة إضافة برومبت جديد

ملفّ JSON واحد لكل غرض، باسم يقول الغرض (`poster-dark-to-light`, `reel-cover`, …)،
ويحمل دائماً `preserve_exactly` و`hard_constraints` — لأن أكثر ما يفسد الناتج هو أن
النموذج «يحسّن» شيئاً لم يُطلب منه.
